# Нейроразвитие дома

Telegram-бот в режиме polling и кабинет специалиста. Исходные требования — [план](docs/planning/developer-plan.md), [14 эпиков](docs/planning/epics/E00.md), [матрица администрирования](docs/planning/admin-matrix.md).

Версия 0.1 — техническая предварительная версия с закрытыми продажами и неподготовленным публичным содержанием. Она **не означает приёмку всех 96 задач**. Фактическое покрытие и ограничения перечислены в [протоколе](docs/release/acceptance.md).

## Локальный запуск

Нужны Python 3.10+, ffprobe (пакет ffmpeg) и virtualenv. Docker не требуется.

```bash
python3 -m virtualenv .venv
.venv/bin/pip install -r requirements.lock
cp .env.example .env
chmod 600 .env
# Заполнить BOT_TOKEN и ADMIN_TELEGRAM_IDS. Секреты в Git не добавлять.
.venv/bin/python -m marina.cli init
.venv/bin/gunicorn --bind 127.0.0.1:8075 --workers 2 --threads 2 'marina:create_app()'
```

В отдельных процессах:

```bash
.venv/bin/python -m marina.cli poll
.venv/bin/python -m marina.cli worker
```

Polling нельзя запускать одновременно с другим потребителем getUpdates этого бота. Программа проверяет существующий webhook и не удаляет его автоматически. TELEGRAM_WEBHOOK_SECRET нужен и при polling: платёжные обновления передаются внутреннему проверенному обработчику. Это случайная отдельная строка, а не токен бота.

До подключения HTTPS-домена кабинет доступен на сервере локально. Для своего браузера:

```bash
ssh -L 8075:127.0.0.1:8075 <пользователь>@<сервер>
```

Команда `/id` показывает Telegram ID для настройки `ADMIN_TELEGRAM_IDS`. Allowlist-администратор открывает `/admin` и управляет сущностями, файлами, операциями, доступом и аудитом прямо в Telegram; чувствительные действия запрашивают причину. `/login` не выдаёт браузерный код и сообщает, что Mini App не используется. `/queue` открывает очередь, `/material` сохраняет текст исходника как черновик.

## Подготовка содержания

Администратор сначала публикует условия обработки данных; клиент принимает конкретную редакцию до создания профиля. Затем специалист создаёт методику с источником, правами, вопросами, баллами, диапазонами, ограничениями и контрольными примерами. Для упражнений загружается MP4, выполняется техническая проверка и подтверждается просмотр специалистом. Черновик, утверждение и публикация — разные действия. Новая версия сохраняет старые результаты и снимает предыдущую редакцию с новых предложений.

Тарифы не предзаполнены. Для покупок нужны опубликованные коммерческие правила и тариф соответствующей валюты, согласованные условия, готовые материалы и подтверждение готовности запуска. В Telegram цифровые продажи доступны через Stars. Веб-продажи Lava.top закрыты до отдельного согласования поверхности, настройки offer с ценой через API и проверки интеграции. Вторая оплата одного намерения попадает в сверку, повторное исполнение не происходит.

Модель ИИ и её лимиты задаются опубликованной настройкой. Нужны OPENAI_API_KEY, разрешение передачи текста в политике данных и утверждённый шаблон. Нет модели по умолчанию. Ручной отчёт доступен независимо от ИИ; его точная редакция обязательно утверждается специалистом.

## Проверки

```bash
.venv/bin/pip install -r requirements-dev.txt
.venv/bin/python -m playwright install --with-deps chromium
.venv/bin/python -m pytest -q
.venv/bin/ruff check marina
.venv/bin/ruff format --check marina tests
```

Тесты используют временные SQLite-БД и искусственный контент, который не загружается в рабочую базу. Реальные платежи и запросы платному ИИ в проверках не выполняются. Браузерная проверка использует настоящий Chromium. Инструкции сервера, резервного восстановления и отката — [runbook](docs/release/runbook.md).

Все изменения проходят PR в develop. Создание и изменение main требуют отдельного разрешения владельца на конкретный коммит; общий запрос реализовать эпики этого разрешения не заменяет.

## Первичный просмотр видео и CRM

После задания клиент отправляет видео через кнопку «Прислать видео специалисту». До приёма файла нужны опубликованные условия и согласие. Специалист открывает обращение через `/queue` или раздел сущностей в `/admin`: смотрит видео, пишет и отправляет мини-заключение, затем приглашает на полную диагностику. Кнопка клиента создаёт заявку на время; подтверждение и завершение встречи обновляют CRM. Ответственный, комментарии и следующий контакт доступны в Telegram-карточке. Подробнее — [маршрут CRM](docs/planning/video-crm.md).
