# Порядок разработки

Рабочие изменения проходят PR из feature/fix/docs-веток в develop. Первое наполнение пустого репозитория выполняется в develop.

main создаётся и изменяется только с отдельного явного разрешения владельца на конкретный проверенный результат. Общий запрос реализовать эпики не заменяет это разрешение.

Поведение разрабатывается через RED → GREEN → рефакторинг; сущности получают административное управление и аудит. Эпик закрывается после фактической реализации и приёмки, не по публикации документации.
