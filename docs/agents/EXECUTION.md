# Персональный интервал касаний

База: `18e8beb505b3a7606bcd55830e42b7f62cac0059` (`develop` и production).
Прямой запрос владельца: одному клиентскому аккаунту назначить интервал
5 минут вместо суток, не возвращая административный доступ.
Идентификаторы аккаунта и рабочей policy остаются вне Git.

## Проверено до изменения

- В `funnel.followup_times` клиенты используют снимок 24/48/72 часа, администраторы
  15/30/45 минут. График сохраняется в `followup_due_at` и durable outbox.
- Персональной настройки нет. `operations` policy уже имеет admin API,
  версионирование, валидацию, отдельные approve/publish и аудит.
- У целевого аккаунта роль client; ожидающих касаний нет. Отменённые сообщения,
  завершённые касания и цепочки с записью не возобновляются.
- Доставка повторно проверяет согласие, право, блокировку, stop и запись;
  изменение интервала не должно менять эти ограничения или сроки купона.
- Проверены существующие timing/admin-migration тесты, CI и штатный autodeploy.

## План и критерии

1. Воспроизвести отсутствие персонального графика через опубликованную admin policy.
2. Добавить необязательный валидируемый `followup_interval_overrides` в operations:
   account ID → целое число секунд. Без новых таблиц и идентификаторов в коде.
3. Проверить 5/10/15 минут для выбранного клиента, прежний график остальных,
   сохранение роли client и ограничений доставки. Старые снимки не переписываются.
4. PR в develop, CI точного SHA, штатный выпуск и его проверки.
5. Опубликовать только персональную настройку через admin API; проверить production
   и приватно записать основание, состояние очереди и обратимое отключение.

## Выполнено

- RED через публичный API воспроизвёл суточный график вместо 300-секундного.
- Добавлены проверка существования аккаунта, целочисленного интервала
  60–86400 секунд и чтение опубликованной operations policy при создании графика.
- 38 профильных проверок passed: новый график, реальная SQLite/outbox,
  перезапуск, повтор, изоляция аккаунтов, запрет клиенту изменять policy,
  неверные значения, stop/booking/marketing и прежняя admin-миграция.
- Ruff lint и format --check прошли для итогового изменения.

Статус: локальная реализация готова; CI, выпуск и рабочая конфигурация ожидаются.
