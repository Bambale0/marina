## Оплата консультаций в боте и проверка цен

По уточнению владельца консультация оформляется через Telegram: заявка → предложение времени → подтверждение клиентом → серверный расчёт → email → защищённая страница Lava.top → проверка поступления → подтверждение оплаты. Возрастной сценарий не требует создавать дополнительный профиль ребёнка. Для администратора сохраняется доступ без списания. Цена и условия берутся из сохранённой заявки; клиентские `amount`, `discount`, `product_id` не управляют суммой. Активная скидка закрепляется при записи и сохраняется, если время согласовано после окончания семи дней. Новая заявка без действующего купона оплачивается по полной сохранённой цене.

Защиты: отменённая/неподтверждённая/оплаченная запись не получает новый checkout; позднее или повторное поступление учитывается в финансовом журнале и отправляется на сверку. Повторный webhook не создаёт повторную услугу. Сервис по подключённому коммерческому тарифу нельзя завершить или выдать ссылку встречи до оплаты. Подтверждение времени само по себе оплатой не считается.

При отмене оплаченной консультации создаётся одна задача ручной сверки возврата без удаления поступления, `order_id` или `paid_at`. Задержавшееся подтверждение оплаты не обещает отменённую встречу. Каждая подтверждённая доставка клиенту/администратору сохраняется отдельно, поэтому отказ отправки одному получателю не повторяет уже доставленное другому. Администратор получает прямую кнопку заявки. Неустранимая общей транзакцией Telegram/SQLite авария после внешней отправки до локального ACK по-прежнему может повторить сообщение. До первой записи отозванное право на руководство, возврат и утрата административного доступа исключают скидку; уже закреплённые условия заявки не пересчитываются.

Playwright запускает настоящий Chromium и веб-интерфейс против Flask/временной SQLite. Четыре полных сценария проходят реальные обработчики Telegram `handle_update`, покупку PDF за 490 ₽, проверку поступления, единственную выдачу файла, касания +24/+48/+72, запись и оплату консультации за 3900/3900/3900/4500 ₽. Внешние Telegram/Lava HTTP заменены транспортом тестового провайдера; реальных сообщений клиентам и списаний не выполнялось. Дополнительно воспроизведено и исправлено отображение копеек как рублей в карточке тарифа и поступления; кнопка возврата Stars не предлагается для поступления Lava.

Рабочая БД: четыре тарифа консультаций инициализированы **черновиками**, с ценами/условиями из PDF, `launch_approved=false`, `web_sales_approved=false`, пустым `lava_offer_id`. Репетиция на копии БД и рабочая запись сохранили опубликованные сценарии, BLOB и финансовые факты (0 поступлений, 2 административные выдачи). Манифест `/var/lib/marina/content/consultation-tariffs-draft-20261104.json`; резервная копия `/var/lib/marina/backups/pre-consultation-tariffs-20261104T134950241301Z.sqlite`.

Владелец ответил «создам позже» на создание четырёх консультационных продуктов в Lava.top. Поэтому рабочая оплата консультаций **ещё не активирована**: существующий offer PDF за 490 ₽ для них не используется. До подключения тарифа бот сохраняет подтверждённое время, сообщает сохранённую цену и недоступность оплаты, не выдаёт фиктивную ссылку. Для активации нужно добавить реальные consultation offer ID с ценой через API, проверить условия запуска, утвердить/опубликовать тарифы, опубликовать commerce-policy со scope `consultation` и актуальной офертой, затем привязать `consultation_product_id` в новой редакции каждой возрастной воронки. Поля и шаблон правил доступны в админке. Для старого прохождения разрешён поиск только тарифа того же возраста в текущей воронке; цена/условия заявки при этом не заменяются.

Отдельные основания полного коммерческого запуска (политика данных, согласия и реальная операционная приёмка) остаются открытыми, как указано выше. Код не объявляет их выполненными.
