# Видеоразбор: без ограничения длительности — 05.11.2026

Владелец уточнил требование во время функционального аудита: «видео по 60 секунд — не ограничивай время роликов». Это уточнение заменяет прежний лимит из авторского описания. Количество роликов и срок ответа задаются существующими правилами продукта.

## Изменение

Загрузка `video_task` больше не ограничивает длительность MP4. Это действует для новых заданий и для уже созданных задач со старым `rules.max_video_seconds=60`. Проверка настоящей видеодорожки через ffprobe, формат, размер файла, согласие, статус задания и права доступа продолжают выполняться.

В приглашении Telegram, уведомлении о назначенном задании и веб-форме удалена граница в секундах. Новый исходный JSON и генератор конфигурации не добавляют `max_video_seconds`; редактор новых правил не предлагает устаревшее поле. Историческое значение обозначено как неприменяемое.

Старые снимки маршрутов и задач не переписываются. При повторном создании задачи по исторической заявке прежнее поле сохраняется в payload, чтобы совпал сохранённый fingerprint идемпотентности. Загрузка это значение не использует. Повтор возвращает тот же объект, без нового задания или уведомления.

## Проверка

До исправления два реальных MP4 на 61 и 601 секунду получили HTTP 422. Отдельный тест воспроизвёл регрессию первоначального изменения: повтор старой задачи с сохранённым fingerprint вернул HTTP 409. После исправления совместимости все 8 новых regression-проверок прошли.

Новые проверки покрывают оба ролика для новых и исторических задач, сохранение исходных байтов, запрет доступа чужому пользователю, оба текста Telegram, defaults без изменения опубликованной policy и повтор запроса к исторической задаче без дублирования.

Целевой существующий набор: 38 passed, 1 deselected. Единственный исключённый сценарий требует отсутствующий в локальном окружении Chromium. Тесты используют временные SQLite и подменяют внешние транспорты Telegram/Lava; настоящих сообщений и списаний не было.

Полный повторный локальный прогон после исправления: 355 passed, 3 failed и 5 errors за 92,44 с. Все 8 непройденных случаев остановились на запуске отсутствующего Chromium 1187; продуктовых падений среди остальных тестов нет. Ruff check, format (72 файла), compileall, синтаксис обоих JS и git diff check прошли. Браузерный сценарий обновлён под подпись без секунд; его фактическое исполнение должно подтвердиться CI точного commit.

## Граница результата

Этот протокол относится к исправлению кода. Применение к рабочему серверу и проверка через настоящий Telegram в этой сессии не выполнены. Снятие ограничения длительности не закрывает отдельные выводы аудита об обязательности аудиоответа, учёте оплаты и контроле ручных сроков специалиста.
