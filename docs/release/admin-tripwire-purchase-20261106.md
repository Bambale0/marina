# Администратор проходит трипваер через кнопку покупки — 06.11.2026

Владелец уточнил: администратору нужна вся обычная последовательность скрининга, результата и платного предложения; только нажатие покупки открывает доступ без списания. Старое право другого прохождения не должно заменять предложение кнопкой открытия.

Ранее owned_guide находил возрастное право администратора независимо от прохождения. Его использовали API результата, уведомления результата/оффера и purchase, из-за чего повторный скрининг сразу предлагал открыть старый PDF. Теперь для администратора право должно относиться к текущему funnel_run; для клиента по-прежнему действует повторное открытие купленного возрастного руководства. Старые права, заказы и платёжные записи не изменяются.

После покупки текущего прохождения сохраняются обычные выдача, отметки доставки и дальнейшая воронка. Новое прохождение создаёт самостоятельный административный заказ только по кнопке покупки; повторные запросы того же прохождения используют один заказ. Повторный callback покупки больше не запускает прямое скачивание одновременно с очередью выдачи. Отдельная кнопка открытия остаётся способом повторного скачивания.

Пять регрессионных сценариев сначала воспроизвели дефект: четыре возраста и восстановление старого owned_guide_id через resume. После исправления 22 целевых проверки прошли: первая/повторная воронка, настоящие callbacks покупки, отсутствие PDF до покупки, одна выдача после двойного нажатия, два административных исполнения для двух прохождений, отсутствие receipts/payment_attempt и обращений к платёжному провайдеру. Существующие проверки обычных повторных покупателей, блокировки отозванного доступа и отсутствия административного доступа после снятия роли также проходят. Полный состав подтверждается CI конкретного head.

Публикация: fix-ветка → develop после CI → штатный deploy.sh. Main не изменяется. Проверка на копии рабочей базы использует подменённые внешние транспорты; клиентам не отправляются тестовые сообщения и реальные списания не выполняются.
