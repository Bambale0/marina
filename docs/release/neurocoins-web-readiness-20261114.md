# Нейро-коины — подготовка отдельной веб-продажи (14.11.2026)

## Фактическое состояние

- В `develop` работает технический кошелёк, журнал `neurocoin_ledger` и 1 НК = 1 ₽.
- Добавлен самостоятельный веб-экран `GET /wallet` и статический `/static/wallet.js`: вход по одноразовому коду клиента (команда `/login` в **личном** чате), чтение баланса, список опубликованных пакетов и тарифов, электронная почта для чека, подтверждение опубликованных условий, запрос счёта, ручная проверка статуса.
- `/wallet` имеет строгую CSP `frame-ancestors 'none'` и не связан с Telegram menu/purchase CTA. Новые браузерные сессии используют `sessionStorage`, без публикации токенов в URL.
- Для новых POST `/api/wallet/topups` и `/api/orders/{id}/checkout` с service=neurocoins сервер требует точный HTTPS `NEUROCOINS_WEB_ORIGIN`, совпадающие Host/Origin, `Sec-Fetch-Site=same-origin` и `Sec-Fetch-Mode=cors`. Это техническая защита от случайных внутрителеграмных и кросс-сайтовых вызовов; **не является криптографическим доказательством, что браузер запущен вне Telegram**, и не заменяет соответствия требованиям платформ.
- Клиентская метка `surface=external_web` больше **недостаточна** для выставления счета. Счет сохраняет `policy_id` и `terms_accepted_at`, а в веб-форме отображается авторская версия условий из опубликованной policy.

## Незакрытые условия коммерческого запуска

1. **Категория услуги и правила Telegram.** По официальной документации [Telegram](https://core.telegram.org/bots/payments-stars), продажа цифровых товаров и услуг **внутри** бота и Mini App требует Stars, независимо от наличия сайта. При этом [Apple 3.1.3(d)](https://developer.apple.com/app-store/review/guidelines/) и [Google Play](https://support.google.com/googleplay/android-developer/answer/10281818?hl=en) отдельно допускают стороннюю оплату **живых индивидуальных занятий 1:1**, если услуга оказывается человеком человеку в реальном времени, а не доступна как повторяемый цифровой контент; групповые занятия и записанные уроки сюда не относятся. Важно: продажа промежуточной виртуальной валюты «Нейро-коины» не становится автоматически такой же исключённой услугой — нужен отдельный вывод по конечному продукту и Telegram. Формально классифицировать конкретные занятия и способ продажи до включения Lava. Не использовать внешний веб-клик как обход правил.
2. **Самостоятельный сайт.** Выделить и независимо опубликовать HTTPS-origin для внешнего кабинета, настроить `NEUROCOINS_WEB_ORIGIN` на точный origin (без слеша в конце), проверить reverse proxy/TLS и доступность внешним браузером. Не добавлять CTA оплаты в Telegram для цифрового товара.
3. **Утверждённые условия и пакеты.** Автор устанавливает в админке опубликованную `policy(type=neurocoins)` с корректными `terms`, `quote_ttl_seconds`, `packages` (целое `coins` и соответствующий `lava_offer_id`) и `services` (тариф `online_lesson`). Цены и набор пакетов нельзя придумывать.
4. **Настройки Lava.** Проверить, что каждый оффер продаётся через API `POST /api/v3/invoice` в RUB, поддерживает «Цена по запросу API», ключ и URL webhook активны. Подтвердить обратные уведомления по протоколу провайдера; не создавать новый POST для `uncertain` без сверки у Lava.
5. **Реальные платежи и возвраты.** На контролируемой минимальной сумме с разрешения владельца выполнить отдельный сценарий: уникальный счёт → платёж → проверенное receipt → зачисление НК → проверка автопокупки → duplicate webhook → возврат/chargeback → сверка и корректирующая проводка. Возвраты/chargeback сейчас ставятся на ручную сверку; отсутствие завершённого автоматического reconciliation — риск.
6. **Операционное включение.** Только после пунктов выше оператор может включить `NEUROCOINS_LAVA_ENABLED=1` с безопасными тарифами. `NEUROCOINS_BOT_SPEND_ENABLED=0` сохраняется для цифровых услуг, если нет отдельного правового основания; не активировать просто ради тестовой покупки. Сделать резервную копию и smoke с настоящим подписанным webhook.

## Проверка на хосте без средств клиента

- Изолированная SQLite: попытка обойти origin через параметр `surface`, чужой Host, HTTP, отсутствующий Origin, `cross-site` и `navigate` — отказ `403`.
- Одноразовый вход: code 256 бит, TTL 300 секунд, старый код заменяется, повторное использование отклоняется; групповой чат не получает код.
- Без опубликованной policy и двух разрешающих флагов новый чек не создаётся.
- JavaScript проверен компиляцией `node --check`; Chromium UI-test запускается в GitHub Actions, где установлен браузер.

**Документ не подтверждает продакшен-покупку.** Код и схема могут быть выложены с выключенными флагами, но это означает production deployment, а не запуск денежных операций.
