# Аудит проекта «Марина» — 4 ноября 2026

## Вывод

Возрастная воронка и выдача руководств реализованы и проходят автоматические проверки. Полный продукт из плана E00–E13 не готов к коммерческой приёмке: в рабочей БД нет опубликованных занятий, подписки, асинхронного разбора и политики обработки данных. Оплата синхронных консультаций не активирована. Проверки на временной SQLite не заменяют запуск этих продуктов.

Основания: приложенный `Chek-list_priemki_Marina.xlsx` (123 функциональные проверки, 57 проверок материалов, 13 вопросов), действующий код и [протокол](acceptance.md). Поздние решения из протокола рассматриваются отдельно от первоначального чек-листа. В этом аудите авторские материалы и решения не утверждались заново, статусы исходного XLSX не менялись.

Проверенная база кода: `0c94d33a11d5a01bc7f9bc05ca29d4a79a6cfbd4`, ветка `develop`. На рабочем сервере `neuron` symlink `/opt/marina/current` указывает на тот же SHA. Проверка рабочего состояния выполнена 04.11.2026 около 20:20–20:27 МСК. Исправление доступа ниже подготовлено отдельно в `fix/marina-audit-lesson-access-20261104`; оно не развёрнуто этим аудитом.

## Воспроизведённый и исправленный дефект

**Связанные пункты:** TRN-02, TRN-07, ADM-08, REL-04.

Через публичный API воспроизведён обход окончания доступа:

1. Родитель запускает готовое занятие, начинается пробный период.
2. За секунду до завершения trial запускает занятие последнего дня.
3. На точной границе окончания `GET /api/lessons/<id>` правильно отвечает 403.
4. `POST /api/lessons/start` с прежним или новым ключом возвращал 200 и содержимое того же занятия.

Причина: возврат существующего занятия дня и возврат из таблицы идемпотентности обходили проверку текущего права. Это подтверждённый дефект, а не предположение по статическому чтению.

Исправление в `marina/training.py`: после получения результата идемпотентного запуска выполняется общая `lesson_access`, используемая при чтении занятия. Оно сохраняет прежний объект и дедупликацию, но проверяет право при каждом ответе.

Новые регрессии в `tests/test_training_access_expiry.py` до исправления дали **2 failed**, после — **2 passed**. Проверены прежний/новый ключ, точная граница trial, отсутствие содержимого в отказе, восстановление доступа через административную выдачу подписки с возвратом того же занятия и повторная блокировка после отзыва подписки. Trial не продлевается повторным запуском.

## Расхождения исходного чек-листа и текущего протокола

- Stars указан как дополнительный маршрут; текущая конфигурация включает только Lava. Это изменение объёма, а не повод молча включить второй провайдер.
- Бесплатный PDF зелёной зоны в текущем протоколе отменён; старые требования выдачи требуют актуализации.
- Заголовки `[Вопрос N из 6]` убраны из Telegram-представления; тесты проверяют сохранение текста, вариантов и баллов.
- Для 5–7 XLSX требует исходный файл без изменений. Рабочий digest — `3d9525…d407fa`, в прежнем протоколе исходник — `711d70…73907`. Совпадение рабочей версии с протоколом не доказывает согласование этого расхождения с XLSX.
- Консультация по созвону и асинхронный разбор не объединяются под одной отметкой готовности.
- В протоколе фигурируют более поздние решения по возрастам, касаниям и промокодам. Лист «Решения» содержит 13 исходных вопросов; наличие кода не заменяет авторское подтверждение спорных правил.

## Проверки кода

Среда этого прогона: Linux, Python 3.12, зависимости из `requirements-dev.txt`, ffprobe и настоящий Chromium 140 (Playwright 1.55). CI проекта использует Python 3.10, поэтому результат CI точного PR нужно проверить отдельно.

- До исправления: 268 passed без браузерных файлов; отдельно 6 passed в браузерном/ценовом наборе.
- После исправления: полный набор **276 passed in 77.49s**, включая Chromium и две новые регрессии.
- После усиления новых регрессий восстановлением и отзывом права: **2 passed**; дополнительного изменения production-кода не было.
- Ruff check и format check, compileall и diff check выполняются перед публикацией ветки.
- Внешние Telegram/Lava/ИИ заменены на транспортной границе, SQLite настоящая временная. Тесты не создавали рабочих списаний или сообщений.

Штатный release gate на рабочем сервере в этом аудите не получен: при запуске системным Python отсутствует dotenv; в runtime-venv отсутствует pypdf. Dev-зависимости на рабочий сервер не устанавливались. Приведённые выше проверки БД и конфигурации выполнены отдельными запросами только на чтение и не обозначаются как успешный запуск gate.
