# Видеоразбор малыша: динамическая оплата и выпуск — 16.11.2026

## Изменения

- Выбор «Другой возраст» → «Заказать видеоразбор малыша» создаёт неоплаченную заявку `awaiting_payment` и не создаёт оплаченной задачи.
- Стоимость берётся из серверного снимка опубликованного маршрута, а не из параметров кнопки или клиента. Каждому заказу соответствует счёт Lava с `amount`, `currency=RUB`, `offerId` отдельного продукта.
- До подтверждения получения платежа по серверному Lava API нельзя выдать задание, загрузить MP4 или отправить задание на разбор. Проверяется не только клиентский интерфейс, но и API.
- Подтверждённая оплата единожды переводит задачу в `requested`, отправляет клиенту подтверждение и сообщает администратору о необходимости выдать задание. После задания клиент загружает своё видео; отправка специалисту и результаты сохраняют существующий порядок.
- Webhook подписан отдельным ключом, статус Lava проверяется сервером, событие обрабатывается идемпотентно. Конфликтующие, поздние и вторичные платежи записываются в receipts/reconciliation, не выдавая услугу повторно.
- Ручное подтверждение специалистом (с причиной и audit) остаётся резервным путём. Администраторы не получают бесплатный auto-fulfill услуги `video_task`; механизм безопасности кошелька `neurocoins` сохраняется.

## Граница коммерческого запуска

- `VIDEO_TASK_LAVA_ENABLED=0` по умолчанию, а `LAVA_VIDEO_TASK_OFFER_ID` должен указывать именно на опубликованную консультацию «Видеоразбор малыша» с режимом **«Цена по запросу через API»**. Цена в запросе выставляется динамически для заявки, не настраивается в Lava вручную для каждой продажи.
- При отсутствии разрешения или `offerId` бот не показывает клиенту нерабочую кнопку оплаты; эндпоинт расчёта также возвращает 503. До активации онлайн-оплату не обещать.
- Проверка продакшн-окружения 16.11: API ключ и ключ вебхука присутствуют; `LAVA_VIDEO_TASK_OFFER_ID` отсутствует. Read-only `GET /api/v2/products?feedVisibility=ONLY_HIDDEN` возвратил HTTP 200 и 6 записей на странице, но продукт с очевидным названием видеоразбора не обнаружен. Динамический счёт **не создавался**, реального тестового списания и возврата нет.
- Важно: для продажи **цифровой услуги внутри Telegram** применяются правила оплаты Telegram Stars, а сторонние платёжные ссылки запрещены. Персональный видеоразбор требует определения юридической/платформенной категории; не включать Lava в Telegram, пока право на выбранный способ продажи не подтверждено.
- Реальная приёмка после разрешения: опубликовать отдельный продукт, установить id в секретном серверном окружении, выполнить контрольное списание через фактический callback → read-only API GET → единственную квитанцию → подтверждение клиента и уведомление администратора → задание → MP4 → доставку. Отдельно проверить refund/chargeback, SLA webhook и журнал сверки.

Источники: https://faq.lava.top/article/83555 ; https://developers.lava.top/en ; https://core.telegram.org/bots/payments-stars ; https://telegram.org/tos/bot-developers .

## Результаты проверок

CI, production-деплой и боевой платёж следует фиксировать только после фактического выполнения; слияние в `develop` само по себе не подтверждает коммерческий запуск. `main` не изменять.
