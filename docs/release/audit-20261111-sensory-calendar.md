# Аудит «Марины» и подключения сенсорного календаря 0–3 года — 11.11.2026

## Решение и границы

Проверены исходники `Bambale0/marina` в `develop`, действующий релиз `18e8beb505b3a7606bcd55830e42b7f62cac0059` на хосте `neuron`, штатные API публикации материалов, read-only показатели production SQLite и переданный владельцем двухстраничный PDF.

**Результат:** PDF воспроизводим и сохранён как исходный артефакт, но **не загружен в production BLOB и не выдан клиентам**. Его контрольная сумма и факт отсутствия публикации описаны в `docs/content/sensory-motor-calendar-0-3.manifest.json`. Файла PDF в Git нет: по действующим правилам проекта авторские материалы хранятся за пределами Git.

**Не выполнено:** допуск клинического содержания, импорт в файловое хранилище «Марины», утверждение материала и изменение опубликованного `consultation_routes`. Ни одна финансовая запись, клиентская заявка, право, активный сценарий или материал не изменялись.

## Цепочка выдачи и установленная первопричина

1. В `consultation_routes` есть опубликованная ветка `baby_0_2`, с `required_videos=3`, `response_hours=24`, `gift_text` и `material_filename`.
2. Production `baby_0_2.material_id` **пустой**, а прямое условие `material_ready` требует опубликованный материал и PDF BLOB.
3. `marina/consultation_journey.py` не разрешает создать lead вида `download` без `material_ready`. В `marina/bot.py` выдача привязана к этому маршруту и согласию пользователя.
4. Существует `POST /api/admin/content` → `POST /api/admin/content/<id>/asset` → `PATCH` с `asset_id` → `approve` → `publish` → публикация новой `consultation_routes` policy. Это правильный административный контур, обходить его прямой правкой SQLite нельзя.
5. В `scripts/publish_document_release.py` уже есть явная блокировка готовности `MOTOR_PDF_NOT_AVAILABLE`. Снимать её вручную без BLOB нельзя.

**Почему не загружено автоматически:** у подключённого SentinelX `file_ops.writable_paths=[]`. Попытка загрузки вложения по ID в /var/lib/sentinelx/uploads вернула `path_not_allowed`. Это ограничение прав доступа к передаваемому файлу, а не ошибка целостности самого PDF. Менять политику SentinelX или подменять наличие файла не следует. Исходный PDF сохранён в постоянной библиотеке ChatGPT в `/Marina/Материалы/0-3/`, но эта библиотека **не является** серверным хранилищем BLOB или Git.

## Найденные проблемы и приоритет

| Уровень | Проблема | Влияние / действие |
| --- | --- | --- |
| P0 для релиза PDF | `baby_0_2.material_id` пуст | Нет клиентской выдачи. Импортировать файл, зафиксировать SHA, утвердить и привязать опубликованный ID |
| P1 | Диапазон PDF «0–3 года» и маршрут `baby_0_2` | Нужна явная возрастная граница для клиента с ровно 3 годами; существующий скрининг начинается с 3–4 |
| P1 | PDF полностью растровый; визуальный CTA не нажимается | Добавить проверенный контакт как PDF Link-аннотацию после утверждения URL; при необходимости сформировать доступную текстовую версию |
| P1 | В `/menu` пока 4 кнопки, тогда как последняя продуктовая схема содержит 6 + канал | Отдельная задача на 2×3 и навигацию; не подмешивать в релиз PDF |
| P1 | Кошелёк из меню информационный, ledger/пакеты не реализованы | Нельзя обещать пополнение/оплату из баланса до целостного финансового контура |
| P1 | Административный статус `paid` без `receipt` | Риск неверных метрик дохода/исполнения; различать `admin` и реальную оплату |
| P2 | `upload_asset` доверяет MIME PDF из формы и ограничению размера, но не проверяет magic/валидность PDF | Только админ может загрузить файл, но возможна публикация некорректного PDF; добавить технический PDF preflight и отрицательный тест |
| P2 | Редакционная проверка утверждений о медицинских «красных флагах» не задокументирована | Перед публикацией требуется утверждение специалистом и проверка трактовок возрастных норм |

1. Подтвердить с автором точный текст и возрастной охват 0–3, согласовать, какой Telegram-контакт должен быть на CTA; исходник сверить по SHA из manifest.
2. Через разрешённый оператором файловый транспорт разместить исходный PDF в приватном каталоге `/var/lib/marina/content` (не в Git, не в каталоге релизного кода). Не ослаблять общие разрешения SentinelX для этого.
3. Выполнить резервное копирование SQLite, создать `material` через административный API, прикрепить PDF BLOB, сохранить `asset_id`; затем пройти отдельные `approve` и `publish` с причиной и аудитом.
4. Создать новую версию `consultation_routes` с `baby_0_2.material_id`, не изменяя действующие консультации и ранее сохранённые снимки; проверить, что `material_ready` истинно, а SHA скачанного PDF совпадает.
5. Провести сквозную проверку для нового родителя: согласие → вход в маршрут малышей → одно PDF-вложение → повторный callback без дубля → приватное повторное скачивание. Проверить журнал, не отправляя неподтверждённые платежи.
6. Повторно запустить проверки и обновить этот аудит статусами реально опубликованного материала и production smoke.
