# E05. Платный PDF с индивидуальной проверкой специалиста

**Статус:** запланирован. **Приоритет:** первая персональная платная выдача в воронке.  
**Зависимости:** E02, E04; структура отчёта и утверждённые материалы из E00. **Связи:** очередь и доставка E12.

## Результат и границы

Клиент покупает отчёт для завершённой попытки скрининга и получает PDF, содержание которого проверено специалистом. Срок услуги — 48 часов после подтверждённой оплаты. ИИ может подготовить текстовый черновик; специалист редактирует его и явно утверждает конкретную редакцию. После этого система собирает и публикует файл, затем уведомляет клиента.

ИИ работает только с разрешённым текстовым контекстом: возрастом, ответами, детерминированным расчётом, экспертными заметками и выбранными утверждёнными материалами. Клиентские аудио, видео и ссылки на них в запрос не включаются. Модель и поставщик пока не выбраны. Отказ ИИ допускает ручную подготовку; автоматическая выдача непроверенного текста не становится запасным маршрутом.

## Сущности и состояния

`Report`, `ReportRevision`, ссылка на попытку и покупку, задание ИИ, версии шаблона/источников, `Approval`, PDF-файл, публикация и доставка. Основной путь: оплачен → черновик → проверка → утверждённая редакция → готовый файл → доступен. Технические ошибки генерации, рендеринга и уведомления имеют самостоятельные состояния, не стирающие срок услуги.

## Задачи по вертикальным срезам

- [ ] **E05-01 — Покупка и срок.** RED: повтор платёжного события создаёт второй отчёт или новый дедлайн. GREEN: один отчёт на исполнение покупки; `due_at` фиксируется как подтверждение оплаты +48 часов. До покупки проверяется завершённость и принадлежность попытки.
- [ ] **E05-02 — Ручной сквозной путь.** RED: специалист не может подготовить отчёт без внешнего ИИ. GREEN: открыть ответы и расчёт, написать редакцию, утвердить, получить PDF в клиентском кабинете. Этот минимальный проход делает услугу работоспособной при сбое генерации.
- [ ] **E05-03 — Текстовый черновик ИИ.** RED: в контекст попадают клиентские медиа или неразрешённые поля. GREEN: явная сборка разрешённого текста, версия шаблона и материалов, ограниченный запрос, таймаут и управляемые повторы. Клиентский текст обрабатывается как данные, без изменения полномочий или адресата.
- [ ] **E05-04 — Редактор и конкретное утверждение.** RED: одобрение A разрешает выдачу новой редакции B. GREEN: утверждение связано с точной неизменяемой редакцией и специалистом; любое изменение содержания требует нового утверждения. История редакций остаётся доступной.
- [ ] **E05-05 — Рендеринг и публикация.** RED: статус «готов» выставлен до сохранения доступного файла. GREEN: собрать PDF из утверждённой редакции, сохранить устойчивый объект, проверить связь и только затем опубликовать. Параллельные задачи не публикуют чужую либо устаревшую редакцию.
- [ ] **E05-06 — Доставка и восстановление.** RED: недоступность Telegram теряет результат или повтор генерации меняет срок. GREEN: результат доступен через защищённый кабинет, уведомление имеет собственные попытки и повтор; новое скачивание может получить обновлённую временную ссылку на тот же файл.
- [ ] **E05-07 — Управление очередью.** RED: специалист не видит приближающуюся просрочку или не может продолжить после сбоя ИИ. GREEN: фильтры по сроку/статусу, техническая причина ошибки, ручная подготовка и разрешённый повтор; действия с оплаченной просрочкой следуют условиям E00.

## Административное управление

Через админку управляются шаблоны отчётов, утверждённые источники, настройки текстового ИИ, задания, редакции, утверждения, файлы и доставки. Специалист видит исходную анкету, методику, расчёт и использованные версии. Изменение шаблона не изменяет уже опубликованный PDF.

Доступны создание новой редакции, её предпросмотр, утверждение, повтор неуспешного рендеринга и уведомления, исправление результата через прослеживаемую новую публикацию. Старое утверждение нельзя перенести на новый текст флажком. Настройки лимитов и паузы продаж доступны в админке; токены не отображаются открытым текстом. Полный перечень операций — в [матрице](https://github.com/Bambale0/marina/issues/2).

## Приёмка: Given / When / Then

1. **Дано:** оплаченный отчёт. **Когда:** обработчик перезапускается и повторяет событие. **Тогда:** остаётся один отчёт с исходным сроком +48 часов.
2. **Дано:** редакция A утверждена, затем создана B. **Когда:** клиент запрашивает B. **Тогда:** B недоступна до отдельного утверждения.
3. **Дано:** ИИ недоступен. **Когда:** специалист пишет текст вручную. **Тогда:** тот же отчёт можно завершить без сброса срока.
4. **Дано:** клиент приложил видео к другой услуге. **Когда:** формируется ИИ-контекст PDF. **Тогда:** видео и ссылка на него отсутствуют в запросе.
5. **Дано:** утверждение есть, рендеринг упал. **Когда:** клиент открывает отчёт. **Тогда:** не показывается ложная доступность PDF, специалист видит сбой.
6. **Дано:** файл опубликован, Telegram не принимает уведомление. **Когда:** клиент открывает кабинет. **Тогда:** PDF доступен, доставка может повторяться отдельно.

## Готовность

**DoD:** ручной и ИИ-пути сходятся в обязательной проверке точной редакции; клиент получает соответствующий PDF; сохраняются происхождение текста, срок, аудит и изоляция файлов. Визуально проверить итоговый PDF с длинными ответами и отсутствующими необязательными разделами. Не публиковать услугу без шаблона, материалов и условий работы специалиста.
