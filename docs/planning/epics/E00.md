# E00. Исходные материалы и решения запуска

**Статус:** запланирован. **Приоритет:** первый проход; подготовка материалов продолжается параллельно с разработкой.  
**Зависимости:** отсутствуют. **Открывает:** E01–E03, E08; условия публикации остальных эпиков.

## Результат и границы

Разработчик и специалист получают единый реестр продуктов, имеющихся материалов, недостающего содержания и решений, влияющих на деньги, сроки и доступ. Каждый пункт имеет владельца, статус и проверяемое основание готовности. Согласованные ответы интервью сохраняются отдельно от технических предложений. Пустые методики, неподготовленные видео и примерные цены не становятся опубликованным продуктом.

В начале есть только упражнения; сами материалы ещё нужно получить и разобрать. Нет готового комплекта вопросов, расчётов и расшифровок скрининга, видеоинструкций и правил подбора. Пакет готовится совместно со специалистом. Автоматические тесты на существование документов не нужны; для будущей логики готовятся содержательные контрольные примеры.

## Задачи

- [ ] **E00-01 — Реестр решений.** Перенести подтверждённые условия из [плана](https://github.com/Bambale0/marina/issues/1) в таблицу «решение / статус / основание / владелец / затронутые эпики». Зафиксировать три разных таймера разбора: основной ответ 48 часов, клиентское окно 24 часа, ответ на уточнение 48 часов. Не трактовать короткие «да» без контекста как дополнительные условия.
- [ ] **E00-02 — Инвентаризация упражнений.** Получить исходники, присвоить устойчивые идентификаторы, отметить источник, формат, права использования, полноту инструкции и потребность в видео. Разметить организационные группы 3–4, 5–6, 7–8, 9–10 лет; ограничения конкретного упражнения задаёт специалист.
- [ ] **E00-03 — Первый методический пакет.** Выбрать с экспертом один инструмент для первого рабочего сценария. Подготовить аудиторию, редакцию, источник и условия использования, вопросы, ветвления, пропуски, расчёт, ограничения вывода и короткий результат. Записать контрольные ответы с ожидаемым результатом, включая границы диапазонов.
- [ ] **E00-04 — Материалы платных услуг.** Согласовать структуру проверяемого PDF, анкету и обязательные вложения разбора, формат основного ответа, шаблоны записи на встречу, программу первого курса. Отдельно составить план производства видео. Владельцем утверждения содержания остаётся специалист.
- [ ] **E00-05 — Денежные примеры.** Подготовить таблицы семейных покупок: общий и отдельные заказы; уход ребёнка; один учитываемый платный профиль во всём аккаунте; раннее продление; будущий период; покупка во время trial. Зафиксировать выбранные дату расчёта семьи, порядок участия, округление, период тарифа и правила поздней оплаты до включения продаж.
- [ ] **E00-06 — Архитектурные решения.** Оформить решения о сервере, интерфейсах, хранилище, очереди и входе. Telegram-бот и Mini App входят в согласованный объём; самостоятельный веб-кабинет для сценария Lava оценивается явно как отдельное проектное решение. Проверить допустимый платёжный маршрут на каждой поверхности по источникам плана.
- [ ] **E00-07 — Реестр управления.** Сопоставить все доменные сущности и бизнес-настройки с [матрицей админки](https://github.com/Bambale0/marina/issues/2). У каждого будущего эпика должны быть операции администратора, валидация и аудит. Первичная загрузка данных не должна превращать дальнейшую работу специалиста в редактирование БД.
- [ ] **E00-08 — Условия эксплуатации.** Определить поставщиков, доступы, политику хранения материалов, согласия, лимиты файлов, доступность специалиста, действия при просрочке и отмене услуги. Ответственный утверждает конкретные условия; разработчик не заявляет соответствие невыбранным требованиям.

## Приёмка: Given / When / Then

1. **Дано:** у упражнения есть текст, но нет видео. **Когда:** проверяется готовность каталога. **Тогда:** оно отмечено как неподготовленное для сценария с видео; отсутствие видно в реестре.
2. **Дано:** выбран скрининг. **Когда:** разработчик воспроизводит контрольные примеры без ИИ. **Тогда:** результат однозначно следует из утверждённого пакета; противоречивый пакет возвращается специалисту.
3. **Дано:** для цены приведён только пример из идеи. **Когда:** проверяется запуск продаж. **Тогда:** продукт остаётся неопубликованным до настройки действующей цены и периода.
4. **Дано:** два ребёнка платные, в корзине выбран один. **Когда:** проверяются денежные примеры. **Тогда:** отдельно зафиксировано, что состав семьи и состав корзины различаются; пример не объявляет выбранного автоматически первым.
5. **Дано:** веб-версия ещё не утверждена по объёму. **Когда:** составляется оценка. **Тогда:** видны отдельные работы и зависимость платёжного маршрута, без скрытого расширения согласованного Mini App.
6. **Дано:** задача затрагивает новую сущность. **Когда:** её считают готовой к реализации. **Тогда:** определены пользовательский сценарий, админские операции, проверки и критерий готовности.

## Админка и готовность эпика

Специалист управляет реестрами материалов и методик, редакциями условий и бизнес-настройками через соответствующие экраны по мере реализации E01–E12. До появления этих экранов документы E00 служат исходным заданием; это не заменяет требование реализовать управление в продукте. Источники, утверждения и изменения должны быть прослеживаемы.

**DoD:** реестр заполнен по фактическим материалам; первый методический пакет имеет владельца; открытые решения привязаны к функции и моменту её публикации; подготовлены денежные примеры и карта админки. Разработку независимых частей можно продолжать при незакрытом условии отдельной продажи. Изменения проходят рабочую ветку и `develop`; `main` — только после явного разрешения владельца по [правилам работы](https://github.com/Bambale0/marina/issues/3).

## Примеры для решения семейной цены

1. Сразу приобретаются периоды для двух, трёх и четырёх детей.
2. Четыре ребёнка продлеваются по одному в разных корзинах при неизменном составе семьи. Ступени не должны превращаться в 8% для каждого.
3. Один ребёнок продлевается сегодня, а у второго доступ закончится завтра.
4. Для другого ребёнка уже оплачен будущий период, который ещё не начался.
5. Профиль вернулся после перерыва; сохраняется ли его место в общем порядке?
6. У родителя остался один учитываемый платный профиль; следующая покупка должна показать полный тариф.
7. Ребёнок покупается во время общего account trial; итоговая дата доступа показана до оплаты.
8. Возвращается одна строка семейного заказа; права других покупок и история занятий сохраняются.

Каждый пример должен получить однозначный ожидаемый состав семьи, порядок, цену и интервалы доступа. Простое объединение пересекающихся интервалов не доказывает, что все дети активны одновременно.

## Как закрывается решение

Зафиксировать ответ владельца, дату, принятый вариант, контрольные примеры, связанные эпики и версию правил. Затем обновить план, административные настройки и проверки. Не отмечать пункт закрытым по факту появления поля в UI. Изменение коммерческого правила для будущих покупок не изменяет прошлые снимки цен и обязательств.
